## Что добавлено в исходники

Настройки → Swiftgram → «Режим призрака»:

- Скрывать онлайн: вместо online отправляется offline. При переключении запрос обновляется сразу.
- Скрывать набор текста и запись: подавляет typing/recording/uploading, сохраняя сигнализацию участия в групповом звонке.
- Не отправлять прочтение: обычные облачные чаты, темы, комментарии и подтверждения просмотра содержимого/упоминаний/реакций. Локальная синхронизация завершается без отправки подавленных операций; уже подавленные прочтения не отправляются при выключении. Последующее обычное прочтение может продвинуть серверную отметку через предыдущие сообщения.
- Сохранять удалённые сообщения: текст уже полученных входящих облачных сообщений записывается перед обработкой серверного удаления. В чате удаление применяется штатно, текст доступен в отдельном архиве.
- Экран архива с подтверждаемой очисткой. Записи разделены базами аккаунтов. Текст отображается буквально, без обработки Markdown.

Все опции изначально выключены. Переключатели общие для аккаунтов этого приложения на устройстве; сами архивы отдельные для каждого аккаунта.

Архив ограничен 200 сообщениями, 4096 символами на сообщение и 512 КиБ текста суммарно. Старые записи вытесняются. Медиафайлы не сохраняются; возможны текстовые подписи. Секретные, запланированные и сообщения с таймером автоудаления/одноразового просмотра исключены. При выключении сохранения существующий архив остаётся до очистки. Удаление аккаунта из клиента удаляет его базу вместе с архивом.

Это не гарантия полной невидимости. Сервер может определять активность по отправке сообщений, реакциям и звонкам; другие сессии аккаунта также отправляют статусы и прочтения. Уже отправленные запросы отменить нельзя. Просмотры историй и секретные чаты используют стандартное поведение. «Прочитать всё» при включённом скрытии прочтения не отправляет массовую отметку на сервер.

Скрытое сервером время посещения собеседника не восстанавливается. Клиент сохраняет стандартные доступные статусы Telegram.

## Сборка через GitHub Actions с Windows

Форк: https://github.com/gandon-pro/Swiftgram-Mod

В Settings → Secrets and variables → Actions нужны два repository secrets: `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`, полученные на https://my.telegram.org/apps. Значения не должны попадать в исходники или обычные repository variables.

В Actions → Build Swiftgram Mod → Run workflow выберите `ipa`. Режим `check` выполняет только разбор синтаксиса Swift и не создаёт приложение. Workflow выбирает Xcode из `versions.json`, загружает зависимости и использует тестовую подпись, поставляемую исходным проектом. Пароль Apple ID не требуется для этой облачной сборки.

После успешной сборки скачайте артефакт `Swiftgram-Mod-IPA-<номер>`. Внутри будет `Swiftgram-Mod-resign-required.ipa`. Перед установкой его необходимо переподписать своим Apple ID, например через AltStore Classic на Windows. Это не готовая подпись для непосредственной установки на iPhone.

В артефакт включаются только IPA, контрольная сумма и краткая инструкция. Сгенерированная конфигурация не загружается и удаляется из рабочей папки runner после завершения. Как в любом Telegram-клиенте, API ID/hash встроены в собранный бинарный файл; GitHub Secrets защищают их от прямой публикации в исходниках и логах, но не от извлечения из IPA.

## Сборка на macOS

Требования именно этого коммита указаны в `versions.json`: macOS 26, Xcode 26.2, Bazel 8.4.2. Полная сборка требует места для исходников и зависимостей.

1. Создайте `configuration.json` из `build-system/template_minimal_development_configuration.json`. Заполните свой `bundle_id`, `team_id`, `api_id` и `api_hash` из https://my.telegram.org/apps. Не публикуйте конфигурацию с секретами.
2. На Mac из корня checkout выполните:

   ```bash
   bash mod-tools/prepare-macos.sh /absolute/path/to/configuration.json
   ```

3. Следуйте корневому `README.md` для подписи, запуска и экспорта приложения. При использовании облачного Mac понадобятся собственные настройки подписи и профили. Windows может хранить и изменять исходники, но не выполняет Xcode-сборку iOS.
4. Для командной сборки с подготовленной директорией подписи используйте официальный интерфейс сборщика:

   ```bash
   python3 build-system/Make/Make.py --cacheDir="$HOME/telegram-bazel-cache" build \
     --configurationPath=/absolute/path/to/configuration.json \
     --codesigningInformationPath=/absolute/path/to/codesigning \
     --buildNumber=100001 --configuration=release_arm64
   ```

Перед распространением используйте собственное название/иконку и соблюдайте условия лицензии исходного проекта. Изменённые исходники опубликованы в личном форке, сборка запускается через GitHub Actions без создания публичного Release.

## Обязательная проверка двумя тестовыми аккаунтами

1. При выключенных опциях проверить обычные прочтения, typing и online.
2. Включить скрытие онлайна в открытом приложении и проверить переход во вне сети со второго аккаунта. Выключить и проверить восстановление статуса.
3. Проверить typing, запись голосового и отмену typing. Повторить после перехода приложения в фон и обратно.
4. При скрытии прочтения открыть личный чат, группу, тему и комментарии. На втором аккаунте прочтение не должно обновляться. Повторить с голосовым сообщением, упоминанием и живой геопозицией. Убедиться, что нет постоянных повторов сетевых операций.
5. Выключить скрытие прочтения, прочитать новое сообщение и проверить штатное обновление отметки.
6. Включить архив, получить текст/подпись и удалить их со второго аккаунта. Проверить архив, перезапуск, дубликаты и очистку. Проверить текст с `[]()*_` — символы должны сохраняться буквально.
7. Проверить, что сообщения, не полученные клиентом, исходящие, секретные и с автоудалением не попадают в архив.
8. Переключить аккаунты: архивы не должны смешиваться. Получить больше 200 удалений и проверить вытеснение старых записей.

На Windows синтаксис можно проверить с Python 3.13 и указанными версиями пакетов (tree-sitter 0.26.0 падает в Windows при использовании этой версии грамматики):

```powershell
py -3.13 -m pip install -r mod-tools/requirements-validation.txt
py -3.13 mod-tools/validate-syntax.py
```


## Настройки мода и оформление

- Раздел Nigga расположен после Swiftgram Pro и перед My Profile.
- Режим призрака одним переключателем скрывает онлайн, набор текста и прочтение.
- Удалённый входящий текст остаётся в чате с прозрачностью 50%; до 200 сообщений.
- Выключение удалёнок убирает сохранённые удалённые строки из текущего чата аккаунта;
  архив очищается отдельно. Фото, файлы, секретные и исчезающие сообщения исключены.
- Название на рабочем столе: Niggagram. Иконка: присланное пользователем изображение.
- Итоговый IPA: Niggagram-resign-required.ipa, bundle ID ph.nigga.graph.
  После переименования пакет требует повторной подписи, включая расширения.
  Новый bundle ID означает отдельное приложение: данные старой установки не переносятся.

## Обновление: файлы, призрак и фоновые удалёнки

- Верхний бейдж: NIGGAGRAM, цветной портрет и оранжевый фон.
- Призрак: отдельные настройки онлайна, печати, записи, загрузки файлов/медиа,
  прочтения, просмотра историй и других индикаторов. Главный переключатель сохраняет выбор.
- Кружки: переключатель стандартных 30 / запрошенных 60 FPS. Частота зависит от
  камеры и режима; двойная камера сохраняет штатное ограничение.
- Файлы из «Файлов» импортируются как копии. Отсутствие security scope для
  локального URL больше не отменяет отправку. При ошибке чтения показано сообщение.
- Удалёнки сохраняются также при сверке истории после переподключения и для
  своих сообщений, удалённых собеседником. Обычные медиа сохраняются как ссылки;
  содержимое не скачанных до удаления файлов может быть недоступно.
- Фоновая опция использует разрешённое iOS время, push-пробуждения и BGAppRefresh.
  Запрос периодического обновления имеет earliestBeginDate через 15 минут, однако
  фактическое расписание определяет iOS. После принудительного закрытия постоянное
  сканирование невозможно; не полученные этим клиентом сообщения не восстановить.
- Секретные, исчезающие и view-once сообщения не сохраняются.
- Скрытие индикатора отправки не скрывает сам отправленный файл от получателя.

Проверка на настоящем iPhone и измерение FPS остаются обязательной ручной проверкой.


## Push notifications after re-signing

The APNs environment now follows `aps-environment` from the embedded signing
profile instead of assuming that every release IPA uses production APNs.
The same environment is used for account device registration, login push
configuration and app-token metadata. If no profile can be read, the upstream
Debug/Release fallback is retained. This does not grant a missing entitlement.

To diagnose an ESign installation, inspect the **signed** app, not the unsigned
build artifact: the profile and code signature must authorize Push Notifications
for the installed bundle ID (`ph.nigga.graph`). ESign must retain that capability.
The app must also have notification permission in iOS Settings. Telegram's push
provider must support the app's APNs identity; a device token alone cannot
configure that provider. Do not copy another app's credentials.

If `didFailToRegisterForRemoteNotificationsWithError` appears in the device log,
resolve the reported signing/network error first. Successful device registration
does not by itself prove end-to-end delivery. Test with a second account while
the phone is locked. Without working push delivery, background archive updates
are limited to the execution windows iOS actually grants the client.
